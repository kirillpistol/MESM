# MESM: как работает система

## 1. Назначение

MESM (Municipal Economic Shock Monitor) — исследовательская система для муниципальной аналитики. Текущий основной кейс — **город Сургут, ОКТМО 71876000**. Сетка муниципалитетов ХМАО используется как обучающий и сравнительный контекст.

Система решает две связанные задачи:

1. прогнозирует ожидаемую траекторию потребительских расходов;
2. отслеживает отклонение факта от прогноза и проверяет, является ли оно кратким шоком или устойчивым изменением режима.

Ключевая логика интерфейса:

```text
ДАННЫЕ → ПРОГНОЗ → ИЗМЕНЕНИЕ
```

## 2. Какие данные являются основой

Основной целевой ряд — публичные данные СберИндекса по безналичным потребительским расходам на уровне муниципальных образований.

Главный ключ территории — **ОКТМО**. Название муниципалитета используется только для отображения и сопоставления с источником.

Текущий контур:

- Сургут — основной объект;
- ХМАО — обучающая сетка;
- 2023 год — начальная историческая база;
- 2024 год — фактический период проверки;
- периоды после доступных фактических данных считаются прогнозом до появления actual.

## 3. Как проходит расчёт

### Шаг 1. Подготовка данных

Исходные данные сохраняются без изменения в raw-слое. Затем система:

1. проверяет структуру файла;
2. приводит период и числовые значения к единому формату;
3. связывает муниципалитет с ОКТМО;
4. исключает неоднозначные идентификаторы;
5. формирует модельную таблицу `ОКТМО × месяц × категория`.

### Шаг 2. Формирование признаков

Для каждого месяца используются только сведения, которые были известны до прогнозируемого периода:

- расходы за 1, 2, 3, 6 и 12 месяцев до текущего;
- средние и стандартные отклонения за 3 и 6 прошлых месяцев;
- месяц и квартал;
- циклические признаки сезонности;
- относительное изменение к прошлому месяцу и прошлому году.

Это правило защищает от утечки будущей информации.

### Шаг 3. Сравнение прогнозных моделей

Все модели проверяются на одинаковых датах 2024 года. Основная метрика — **MAE**.

Сейчас сравниваются:

- Last Value;
- Seasonal Naive;
- Linear Trend;
- Prophet;
- Grow — модель роста MESM.

Текущий development-лидер — Grow.

### Шаг 4. Ошибка прогноза

Для каждого месяца рассчитывается:

```text
ошибка = факт - прогноз
```

Если ошибка мала, наблюдение считается близким к ожидаемой траектории. Если ошибка велика, запускается контур проверки сигнала.

### Шаг 5. Выявление изменений

Система разделяет два типа событий:

- **краткий шок** — отклонение на 1–3 месяца;
- **устойчивое изменение режима** — отклонение на 6–12 месяцев.

Для online-наблюдения сравниваются CUSUM и Page-Hinkley. Для последующего подтверждения используется PELT.

## 4. Что система делает сейчас

- воспроизводимо рассчитывает прогнозы;
- сравнивает модели на одинаковом периоде;
- хранит источник и SHA-256;
- использует ОКТМО как основной территориальный ключ;
- отделяет реальные данные от синтетических тестов;
- отдельно оценивает ранний online-сигнал и offline-подтверждение;
- выводит бюджетный Reference Layer для экономической интерпретации.

## 5. Что пока не является окончательным

До консультации с администрацией не считаются окончательно утверждёнными:

- нормативные параметры бюджетных ограничений;
- состав допустимых исключений из дефицита;
- формула бюджетной обеспеченности;
- перечень обязательных муниципальных и региональных факторов;
- правила интерпретации сигнала для практического использования.

Программная архитектура сделана так, чтобы эти элементы менялись через конфигурацию или отдельный расчётный модуль без перестройки всей системы.

## 6. Что важно уточнить на встрече

1. Какая формула бюджетной обеспеченности используется в рабочем процессе администрации и региона?
2. Какие доходы входят в расчётную доходную базу?
3. Какие безвозмездные поступления и исключения должны учитываться отдельно?
4. Какие ограничения по дефициту, долгу и обслуживанию долга необходимо применять именно для Сургута?
5. Какие показатели финансисты считают опережающими для оценки состояния муниципальной экономики?
6. Какие данные доступны ежемесячно, ежеквартально и ежегодно?
7. Какие официальные показатели можно использовать как дату подтверждения структурного изменения?
8. Нужно ли разделять собственно город Сургут и Сургутский район во всех аналитических витринах?
9. Какие категории расходов имеют наибольшую практическую ценность для администрации?
10. Каким должен быть итоговый сигнал системы: информационный, предупреждение, подтверждение или сценарная оценка?

## 7. Принцип дальнейшей доработки

Каждое изменение проходит одинаковый цикл:

```text
данные → формула → код → тест → метрики → интерпретация → согласование
```

После встречи корректируются формулы и правила интерпретации, а затем повторно запускаются тесты и модельный benchmark.
