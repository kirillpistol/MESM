# MESM 1.13: самостоятельный источник L3 и завершаемый цикл

MESM — только MESM: собственная серверная база, сборщики, финансовые формулы, панель менеджера и общий отчёт. Он не запускает ядро, не устанавливает L2 и не переключает другие программы. GENESIS расположен отдельно. Сборщики исходных документов также запускаются отдельно по своему расписанию; старт API не скачивает внешние данные.

## Разные серверы
Каждая программа L3 имеет собственную базу, node_id, сертификаты и токен. Между источниками базы не копируются и не объединяются. На сервере MESM можно запустить API без панели; панель остаётся инструментом менеджера для проверки и скачивания отчёта. Собранные у потребителя отчёты хранятся в отдельных каталогах каждого источника.

Локальная проверка: START_MESM_L3.bat (после установки окружения через START_MESM.bat). Старый START_MESM_GENESIS.bat — только совместимый alias запуска MESM API, он больше не запускает GENESIS.

Сервер: задайте свой MESM_API_TOKEN в защищённом окружении и запустите:

`PYTHONPATH=src python -m mesm.access.server --host 0.0.0.0 --port 8765 --tls-cert /secrets/server.crt --tls-key /secrets/server.key --tls-ca /secrets/client-ca.crt`

Нужны реальные ваши DNS/SAN, сертификаты, права файлов и сетевые правила. Внешний интерфейс без TLS запрещён. При --tls-ca клиент обязан предоставить сертификат, дополнительно требуется Bearer token. Ключи и токены в Git не входят. HTTPS-клиент проверяет CA и имя сервера; redirects и env proxies запрещены. Список origin задаётся вручную. Реальные серверы не развёрнуты автоматически: адреса и сертификаты предоставляет владелец.

## Цикл потребителя
1. GENESIS/менеджер подключается к заранее разрешённому адресу и читает GET /v1/node: подтверждает node_id, роль L3, снимок и доступные территории.
2. POST /v1/sessions/open: municipality и snapshot_id. Создаётся ограниченная сессия (15 минут), без запуска ядра внутри MESM.
3. GET /v1/report-package?municipality=...&session_id=...: готовые результаты MESM, период, происхождение и отчёт. Для данных остаётся GET /v1/data; новые клиенты могут передать session_id для проверки активности/территории.
4. GENESIS выполняет свою обработку отдельно. Сборщик отчётов лишь сохраняет пакет; он не является обученной моделью и не имитирует L2.
5. POST /v1/sessions/close: завершение сессии в finally, в том числе при ошибке. Повтор close идемпотентен, пока запись сохранена: до TTL либо вытеснения из ограниченного журнала закрытых сессий. Дальнейший запрос по закрытой сессии отклоняется.
6. GENESIS переходит к другой программе. MESM остаётся в ожидании; новый цикл открывает новую сессию. Те же входы дают тот же snapshot_id и финансовые результаты, хотя ID сессии и время отчёта меняются.

Завершение цикла не удаляет базу и не останавливает весь сервер. Остановка/перезапуск процесса MESM — отдельная операция владельца сервера (служба/контейнер), не скрытый сетевой shutdown. При обрыве соединения закрытие может не подтвердиться: потребитель отмечает это, сессия автоматически истекает. Подтверждённое закрытие обязательно для успешного цикла.

## Пакет и экран
GET /v1/report-package возвращает genesis.l3-report/1 с producer_contract=mesm.report-package/1: source_node, municipality, period, snapshot_id, generated_at, financial_snapshot, budget_calculations, evidence_status, ограничения и report {format,sha256,content}. HTML содержит те же пять согласованных вопросов. Реальные гипотезы и эффект не объявляются доказанными. Кассовые загрузки только в браузерной сессии пока не входят в серверный снимок.

GET /v1/node и все финансовые маршруты требуют авторизации. Выдача остаётся только из каталогизированных наборов MESM. В Git находится код и публичный демонстрационный снимок; при развёртывании замените его собственной базой и уникальным config/l3_node.json. Изолированность реальных серверов зависит также от размещения, полномочий ОС и сети.

## Независимый сборщик отчётов
В отдельном genesis-level-3 находится `level3_data.report_manager`. Он читает вручную заданный список источников из JSON, открывает/закрывает сессии последовательно, проверяет идентичность/снимок/хеш и сохраняет отчёты раздельно. Конфигурация: examples/report_manager.example.json; токен указан именем ENV, не значением.

`python -m level3_data.report_manager --config /config/report-manager.json --output /reports`

Каждый запуск — новый каталог с collection.json и index.html. Ошибка одного узла отмечается отдельно, остальные проверяются. Нет суммирования показателей разных источников и общей муниципальной базы. Нет скрытого повторения задач или вечного фонового цикла. Плановое повторение настраивается владельцем менеджера в системном планировщике после проверки одного цикла. Системы другого типа должны реализовать тот же контракт пакета или отдельный адаптер.
