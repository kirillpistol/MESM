# MESM — L3: закрепление методики и периодические обновления

Версия документа: 1.0.0. Дата: 06.10.2026. Владелец формул муниципальных расчётов — MESM. Документация описывает программную реализацию, не заменяет исходные документы и не является утверждённой администрацией методикой.

## Что закреплено
- config/formula_registry.json — машиночитаемый реестр формул текущей серверной выдачи. Для каждой формулы заданы постоянный ID, версия, поле результата, выражение, входы, единица, реализация, смысл, проверки и предел вывода.
- docs/30_function_reference.md — подробные математические пояснения и сохранённый исторический указатель реализации; текущий полный перечень объявлений отдельно в docs/40_current_code_index.md.
- docs/31_cash_schema_and_audit.md — отдельные правила кассовой нормализации и аудита. Кассовые сценарии не выдаются за официальный серверный факт.
- docs/05_formula_registry.md — общий справочник обозначений. Формулы официальных источников хранятся отдельно.
- docs/38_l3_manager_architecture.md и ADR-0001 — границы L3 и завершаемый цикл.

Пять формул машинного реестра относятся только к budget_calculations и fiscal_panel. Они не объявляются полным перечнем всех алгоритмов MESM. Нельзя заменять знаковое income_plan_deviation показателем official_i13 с ограничением отрицательных значений нулём. Финансовая панель и функции официальной методики решают разные задачи.

## Что получает GENESIS
GET /v1/methodology возвращает закреплённый снимок документации: formula_registry, тексты документов, SHA-256, хеши файлов реализации и methodology_id. Это чтение, не выполнение строк формул; eval и загрузка кода по сети не используются.

GET /v1/node сообщает methodology_id и адрес методики. report-package включает версии формул, идентификатор методики, адрес /v1/methodology и хеши документов. Полные тексты не передаются внутри 64 KiB задачи ядра: их читает внешний потребитель через API MESM. Потребитель может сохранить методику рядом с пакетом; документация остаётся привязана к своему источнику.

snapshot_id теперь учитывает данные и закреплённую методику/реализацию. Если документация или код расчёта изменились, даже при одинаковых исходных числах новый снимок может иметь другой ID. SHA-256 проверяет неизменность содержимого, а не экономическую корректность или юридическую силу.

## Периодические обновления проекта
MESM будет периодически обновляться: новые источники, схемы, формулы, методы проверки, исправления и визуальное представление. Данные, методика и код обновляются раздельно, со своими версиями. Частота релизов заранее не фиксируется; автоматическое скачивание и применение нового кода не включено.

Релиз выполняется владельцем проекта:
1. Обосновать изменение и перечислить затронутые входы/выходы.
2. Обновить реестр формул и повысить версию изменившейся формулы, если меняются результат, единица, база, обработка null или трактовка. Исправление ошибочной формулы тоже требует новой версии.
3. Обновить кодовый указатель: python scripts/build_code_index.py. Обновить пояснения и документировать несовместимости. Переименование/удаление поля или изменение его смысла требует новой версии соответствующего контракта; добавочное поле документируется как расширение.
4. Проверить реальные подстановки, единицы, отрицательные значения, null, нулевые знаменатели и регрессии. При изменении формул пересобрать производные таблицы, а не оставлять результаты предыдущей методики.
5. Выпустить версию кода и запись в CHANGELOG.md, проверить манифест данных. Не повышать версию формулы при чисто визуальном изменении.
6. Завершить активные циклы, сохранить предыдущие пакеты/версии, развернуть проверенную сборку, перезапустить API и построить новый снимок. Одновременная замена исходных файлов в активном цикле не поддерживается; сервер отклоняет изменившийся снимок.
7. Потребитель перед новым циклом проверяет contract, software_version, snapshot_id и methodology_id. Несовместимый контракт требует обновления адаптера; одинаковые имена полей не разрешают молча смешивать разные методики.

Старый отчёт интерпретируется по закреплённой в нём версии и сохранённому пакету. Автоматическое архивирование всех серверных SQLite-снимков и криптографическая подпись документов пока не реализованы: история релизов хранится в Git, а отчётные пакеты — у потребителя.
