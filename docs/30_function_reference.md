# MESM: действующие функции, формулы и зависимости

Версия кода: `1.11.0`, состояние на 27.09.2026. Этот файл описывает **реализацию в репозитории**, а не утверждённую муниципальную методику. В конце дан пофайловый указатель всех объявленных функций и классов, включая внутренние помощники. Для нормативных оснований и происхождения исходных документов см. [реестр свидетельств](29_source_evidence_register.md), [кассовый контур](28_cash_execution_bridge.md) и [формулы администрации](26_admin_formulas.md).

## 1. Как проходит расчёт

| Этап | Вход → выход | Основные функции | Что проверяется |
|---|---|---|---|
| Получение | архивы, Excel, CSV → извлечённые строки и манифест | `ingest/*`, `fetch_official_sources.py` | формат, путь в архиве, источник, хеш, дата |
| Приём | загруженная таблица → принятая версия или отказ | `data.intake.validate_dataset`, `persist_dataset`; `public_data.pipeline.update_public_data` | обязательные поля, дубли ключей, совместимость контракта, доступность |
| Сопоставление | названия → ОКТМО, YTD → помесячные потоки | `geo.oktmo.resolve_source_names`, `data.ytd.ytd_to_flow`, `budget.cash_execution.monthly_from_ytd` | неоднозначные имена, год, единицы, непрерывность 0503117 |
| Расчёт | строки → признаки и бюджетные показатели | `features.fiscal.*`, `budget.normalization.calculate_budget`, `budget.cash_execution.normalize_cash` | знаменатели, суммы, утверждённые корректировки, дата среза |
| Сравнение | история → прогноз и ошибки | `evaluation.forecast_benchmark.*`, `models.competition_challengers.*` | обучение до прогнозируемой даты, фактические наблюдения |
| Детектирование | ряд → флаги или состояния | `models.changepoint.*`, `models.state_machine.*`, `models.dualstate.*` | пороги, устойчивость, независимые подтверждения |
| Представление | рассчитанные таблицы → экраны и отчёт | `dashboard/*`, `reporting.decision_memo.*` | статус данных и явно помеченные демонстрационные значения |

Файлы `scripts/*` запускают отдельные операции; приложения не должны принимать результат модели за официальный первичный документ. Примеры в `dashboard.cash_view.demo_cash` — синтетические.

## 2. Единицы, время и воспроизводимость

- Денежные суммы в формулах должны иметь **одинаковые единицы** внутри одного вызова (рубли, тыс. рублей или млн рублей). Отношения безразмерны; `0.10` отображается как 10% только на экране. Масштаб исходного бюджета определяется при разборе источника (`ingest.surgut_budget.workbook_unit_scale_to_rubles`).
- `available_at <= as_of` ограничивает видимость кассовых строк; корректировка допустима при `approved_at <= as_of`. Для внешних признаков точку доступности проверяют `public_data.schemas.features_as_of` и `validation.temporal.*`. Дата отчётного периода и дата публикации различаются.
- Для версии формы 0503117 по сочетанию `(месяц, КБК, сторона)` выбирается последняя **доступная** на дату расчёта публикация. Две записи с одинаковым ключом и датой доступности вызывают ошибку. Исходные строки и номер/документ должны храниться для проверки результата.
- Если показатель накоплен с начала года, производный поток для последовательных месяцев одного года равен `YTD_t − YTD_(t−1)`; для января в `monthly_from_ytd` вычитается ноль. Обобщённая `data.ytd.ytd_to_flow` **не** вычисляет поток для первого среза, а требует одинаковые методику, классификацию, область и единицы. Эти две функции имеют разные контракты.

## 3. Формулы, которые действительно выполняет код

### 3.1. Бюджетные признаки (`features/fiscal.py`)

Пусть `I` — первоначальный план, `R` — уточнённый, `A` — исполнение, `P` — ресурсы, `C` — оценка обязательств.

| Функция | Реализованная формула | Смысл и оговорка |
|---|---|---|
| `revision_rate` | `(R − I) / I` | Направление изменения плана. |
| `revision_magnitude` | `abs(R − I) / abs(I)` | Размер изменения без знака. |
| `execution_rate` | `A / R` | Доля исполнения; при нуле плана возвращает `None`. |
| `execution_gap` | `(A − R) / R` | Отклонение от плана; знак зависит от знака `R`. |
| `coverage_gap` | `P / C − 1` | Относительный избыток/недостаток ресурса. |
| `official_i13` | `max(((tax_actual+nontax_actual)−(tax_initial+nontax_initial))/(tax_initial+nontax_initial), 0)` | Техническая реализация показателя; для официальной интерпретации нужна сверка с исходной методикой. |
| `official_i15` | `program_expense / total_expense` | Доля программных расходов. |
| `official_i25` | `q4 / ((q1+q2+q3)/3)` | Отношение IV квартала к среднему I–III. |
| `official_i26` | `utility_compensation / total_expense` | Доля компенсаций. |
| `official_i27` | `overdue_payables / total_expense` | Доля просроченной кредиторской задолженности. |
| `official_i33` | `municipal_debt / own_revenue_base` | Долг относительно собственной базы. |

Все деления в этом модуле при нулевом/отсутствующем знаменателе дают `None` (вместо придуманного нуля). Реестр официальных исходных формул: `config/formulas/official_quality_formulas.yaml` и `data/processed/official_quality_formulas_2024_2025.csv`.

### 3.2. Бюджетные ограничения (`budget/normalization.py`)

Для `B = revenue_base`, `T = transfers`, `E = expenditure`, `D_base = deficit_base` (по умолчанию `B`), `X = eligible_exceptions`, `F = financing_sources`, `λ = deficit_limit_ratio`:

```text
total_revenue = B + T
balance = total_revenue − E
deficit = max(−balance, 0)
deficit_ratio = deficit / D_base
base_deficit_limit = λ × D_base
raw_normalization_gap = max(deficit − base_deficit_limit, 0)
allowed_deficit = base_deficit_limit + X
normalization_gap = max(deficit − allowed_deficit, 0)
financing_gap = max(deficit − F, 0)
recurring_balance = recurring_revenue − recurring_expenditure
structural_gap = max(−recurring_balance, 0)
debt_after = max(current_debt + planned_net_borrowing, 0)
debt_ratio = debt_after / B
debt_headroom = B × debt_limit_ratio − debt_after
debt_service_ratio = debt_service / expenditure_ex_subventions,
                     либо / expenditure, если первая база <= 0
```

В `calculate_budget` внутренний `_ratio` возвращает **0** при знаменателе `<= 0`; это правило прототипа, и ноль здесь не означает доказанное соблюдение норматива. Конфигурационные значения `λ=0.10`, `debt_limit_ratio=1.00`, `debt_service_limit_ratio=0.15` — **настройки пилота, не установленная здесь норма права**. `gap_structure` даёт механический расклад: `structural_overlap=min(structural_gap, normalization_gap)`, остаток — разность. `revenue_base_to_close = normalization_gap/(1+λ)` предполагает, что `deficit_base` одновременно растёт с `revenue_base`; при отдельно заданной базе оценку нужно пересчитать через `apply_scenario` + `calculate_budget`. `automatic_closure_scenarios` строит иллюстративные варианты, а не утверждённый финансовый план. **Бюджетный `normalization_gap` не равен экспертной корректировке кассовых поступлений**.

### 3.3. Месячное кассовое исполнение (`budget/cash_execution.py`)

Исходные суммы по стороне бюджета сохраняются, а утверждённые `ManualCorrection` меняют отдельный аналитический ряд. Перенос суммы между месяцами не создаёт новую сумму. Все поправки требуют ID, основания, документа, утверждающего лица и даты; код проверяет знаки и пределы подтверждённых строк. `ONE_OFF` и `CARRYOVER` исключают указанную сумму из аналитической строки без переноса. `REFUND_REALLOCATION` переносит отрицательный возврат в прежний месяц, `ADVANCE_REALLOCATION` — аванс в будущий месяц.

```text
raw_side_t = сумма доступных на as_of строк по месяцу и стороне
normalized_side_t = raw_side_t + сумма применимых экспертных поправок
recurring_balance_t = normalized_revenue_t − normalized_expenditure_t
cash_balance_t = opening_balance + Σ_{i<=t}(
    raw_revenue_i + raw_financing_i − carryover_i − raw_expenditure_i)
reserve_need_t = max(−cash_balance_t, 0)
real_recurring_balance_t = recurring_balance_t / deflator_t   (если задан)
seasonal_balance_t = Σ_KBK(normalized_revenue_KBK,t / factor_KBK,t)
                     − Σ_KBK(normalized_expenditure_KBK,t / factor_KBK,t)
```

`seasonal_balance` и `real_recurring_balance` независимы: код не создаёт единого ряда «сезонно очищено и дефлировано». При отсутствии коэффициента/дефлятора значение возвращается как `None` (для сезонности с переданной неполной картой выбрасывается ошибка). Коэффициенты передаются извне; автоматической оценки сезонности и индекса цен **нет**. `cash_vs_monthly_plan` вычисляет `raw / monthly_plan` и `(normalized − monthly_plan)/monthly_plan` отдельно для доходов и расходов; при нулевом плане относительный показатель `None`. Статус `OBSERVED`/`ADJUSTED` означает наличие арифметической поправки, а не официальное утверждение месяца.

### 3.4. Прогноз и качество (`evaluation/*`, `models/competition_challengers.py`)

Для истории `y`, прогноза `ŷ`, ошибки `e_i=y_i−ŷ_i`:

```text
MAE = mean(abs(e))
RMSE = sqrt(mean(e²))
R² = 1 − sum(e²)/sum((y−mean(y))²)
WAPE = sum(abs(e))/sum(abs(y))
MASE = MAE/mean(abs(history_i−history_(i−s)))
precision = TP/(TP+FP); recall = TP/(TP+FN)
```

В `forecast_benchmark._metrics` `s=12`, если обучающая история длиннее 12 точек, иначе `s=1`; `competition_challengers.score_forecast` применяет `s=1`. Если знаменатель MAE/R²/WAPE/MASE не определён, benchmark возвращает `NaN`, а `evaluation.metrics.wape`/`mase` выбрасывают `ValueError`; контракты функций не следует смешивать. `roc_auc` вычисляет AUC по усреднённым рангам, `average_precision` усредняет точность на положительных позициях. `expanding_forecast_table` на каждом шаге использует только предыдущие значения: последнее, аналогичный месяц предыдущего года и линейный тренд. `grow_hmao_forecast` обучает CatBoost на `g_t=ln(y_t/y_(t−1))`, восстанавливает `ŷ_t=y_(t−1)×exp(ĝ_t)`, признаки — лаги 1/2/3/6/12, прошлые скользящие средние и стандартные отклонения за 3/6 месяцев, месяц и `sin/cos(2π×month/12)`. Для положительности аргумента логарифма и корректной истории нужны валидные входы. Prophet — отдельный опциональный challenger; выигрыш модели не подтверждён одним демонстрационным прогоном.

### 3.5. Сигналы (`models/changepoint.py`, `models/state_machine.py`, `models/dualstate.py`)

`cusum_flags` берёт среднее `μ` и стандартное отклонение `σ` первых `warmup` значений (если `σ=0`, используется 1), затем `z_t=(x_t−μ)/σ` и `S+_t=max(0,S+_(t−1)+z_t−drift)`, `S-_t=min(0,S-_(t−1)+z_t+drift)`; тревога при `S+_t>threshold` или `abs(S-_t)>threshold`. `page_hinkley_flags` использует обновляемое среднее и накопленный прирост от локального минимума. `pelt_breakpoints` — офлайн-сегментация `ruptures.Pelt(model='rbf')` со штрафом `penalty`, она не даёт ранний онлайн-сигнал.

`HysteresisStateMachine.update` переводит контур через `NORMAL → OBSERVE → WARNING → BREAK_CONFIRMED` при устойчивости выше `on_threshold` и требуемом числе подтверждений; возврат к `NORMAL` требует `k_off` периодов ниже `off_threshold`. Значения по умолчанию нужно калибровать до практического использования. Слияние контуров: `F=2×R+P`, где `R,P∈{0,1}`; `0=NORMAL`, `1=EARLY_WARNING`, `2=FISCAL_DIVERGENCE`, `3=SYSTEMIC_STRESS`. `dual_fusion_score=1−(1−r)(1−p)` — **оценка для разработки, не калиброванная вероятность**. `probability_state` возвращает `UNCERTAIN` при недостаточном разрыве двух лидирующих оценок. Итоговый ReferenceScore ещё не обучен: `models.reference.reference_feature_vector` лишь собирает признаки; `models.interpretation.reference_screening_flags` показывает диагностические флаги, не присваивая официальный `NORMAL/WARNING`.

## 4. Пакеты и запуск

Файл `pyproject.toml` — точная спецификация версий и зависимостей; минимальный Python — 3.11. Базовое ядро не объявляет обязательных сторонних пакетов, но для конкретного модуля нужен его набор:

| Группа установки | Пакеты | Где используются |
|---|---|---|
| `dashboard` | Streamlit, pandas, Plotly, openpyxl, xlrd | экраны, таблицы, графики и импорт Excel |
| `research` | NumPy, pandas, SciPy | исследования, сравнения и преобразования рядов |
| `changepoint` | NumPy, ruptures | офлайн-детектор PELT; CUSUM работает без ruptures |
| `competition` | NumPy, pandas, CatBoost, Prophet | Grow и Prophet; отдельный тяжёлый набор |
| `public-data` | aiohttp, pandas, pandera | загрузка агрегатов и схема валидатора |
| `yaml`, `excel`, `rar`, `dev` | PyYAML; pandas/openpyxl/xlrd; rarfile; pytest | конфигурации, файлы Excel, архивы RAR, тесты |

Windows-скрипт `START_MESM.bat` ставит `dashboard,dev,yaml,research,changepoint,excel`, проверяет справочные данные и быстрый кассовый расчёт, затем запускает Streamlit. `competition`/`public-data` требуют отдельной установки для соответствующих функций. Полная проверка: `CHECK_MESM.bat` или `python -m pytest`.

## 5. Границы текущей версии

Наличие функции в реестре означает, что она реализована, **не означает** наличия производственных данных, утверждённого норматива или доказанной прогностической точности. Оперативная выгрузка УФК и внутренние месячные файлы 0503117 в демонстрационной сборке не предоставлены. Сезонные коэффициенты, дефляторы и экспертные корректировки требуют подтверждённого источника и протокола. Некоторые экранные карточки читают подготовленные CSV. Пользовательский ввод проверяется до публикации, но при изменении формата поставщика контракт и тесты нужно обновить. Следующий этап — согласовать определения с финансовым органом, добавить реальные разрешённые версии документов и провести backtest по дате доступности.
