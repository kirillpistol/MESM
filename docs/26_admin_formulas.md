# MESM: формулы и расчётные блоки

## 1. Статус документа

Это перечень формул, которые **фактически реализованы в текущем коде MESM**. Часть бюджетных коэффициентов пока является технической конфигурацией прототипа и должна быть подтверждена специалистами администрации.

## 2. Прогноз потребительских расходов

Пусть:

- `y_t` — фактические расходы в месяце t;
- `ŷ_t` — прогноз расходов;
- `g_t` — логарифмический темп роста.

В модели Grow (модель роста MESM) прогнозируется не абсолютный уровень, а темп роста:

```text
g_t = ln(y_t / y_(t-1))
```

После прогноза роста уровень восстанавливается:

```text
ŷ_t = y_(t-1) × exp(ĝ_t)
```

Так модель может одновременно использовать муниципалитеты и категории разного масштаба.

## 3. Лаговые признаки

Используются:

```text
lag_1  = y_(t-1)
lag_2  = y_(t-2)
lag_3  = y_(t-3)
lag_6  = y_(t-6)
lag_12 = y_(t-12)
```

Дополнительно:

```text
Δlag_1 = lag_1 - lag_2
pct_lag_1 = lag_1 / lag_2 - 1
YoY_lag = lag_1 / lag_12 - 1
```

## 4. Скользящие характеристики

Среднее за W прошлых месяцев:

```text
RollingMean_W(t) = mean(y_(t-1), ..., y_(t-W))
```

Стандартное отклонение:

```text
RollingStd_W(t) = std(y_(t-1), ..., y_(t-W))
```

В текущей версии W = 3 и 6.

## 5. Сезонность

Месяц кодируется также циклически:

```text
month_sin = sin(2π × month / 12)
month_cos = cos(2π × month / 12)
```

Это позволяет модели понимать близость декабря и января.

## 6. Метрики прогноза

### MAE — основная метрика

```text
MAE = (1/n) × Σ |y_t - ŷ_t|
```

MAE показывает среднюю абсолютную ошибку прогноза в рублях.

### RMSE

```text
RMSE = sqrt((1/n) × Σ (y_t - ŷ_t)^2)
```

Сильнее штрафует крупные ошибки.

### R²

```text
R² = 1 - Σ(y_t - ŷ_t)^2 / Σ(y_t - mean(y))^2
```

### WAPE

```text
WAPE = Σ|y_t - ŷ_t| / Σ|y_t|
```

### MASE

```text
MASE = MAE / mean(|y_t - y_(t-1)|)
```

В реализации challenger-моделей масштаб берётся по среднему абсолютному изменению исторического ряда.

## 7. Ошибка прогноза и стандартизация

```text
e_t = y_t - ŷ_t
```

Для устойчивой к выбросам стандартизации используется медиана и MAD:

```text
MAD = median(|e_t - median(e)|)
scale = 1.4826 × MAD
z_t = (e_t - median(e)) / scale
```

Если MAD равен нулю, используется стандартное отклонение.

## 8. CUSUM

На стандартизированном отклонении поддерживаются положительная и отрицательная накопленные суммы:

```text
S+_t = max(0, S+_(t-1) + z_t - k)
S-_t = min(0, S-_(t-1) + z_t + k)
```

Сигнал формируется, если:

```text
S+_t > h  или  |S-_t| > h
```

где `k` — drift, `h` — порог.

## 9. Page-Hinkley

Метод отслеживает накопленное отклонение наблюдений от обновляемого среднего. В двухсторонней реализации MESM отдельно отслеживается рост и падение. Сигнал появляется, когда накопленное отклонение от предыдущего минимума превышает настроенный порог.

Порог не выбирается вручную «для красивого результата»: он калибруется на путях без шока при заданном бюджете ложных тревог.

## 10. PELT

PELT используется как offline-метод локализации точки изменения. Он минимизирует сумму стоимости сегментов и штрафа за количество разрывов:

```text
min Σ Cost(segment_j) + β × K
```

В MESM используется реализация `ruptures.Pelt(model="rbf")`. PELT не трактуется как ранний online-сигнал.

## 11. Бюджетный блок

Обозначения:

- `R` — доходная база;
- `T` — трансферты;
- `E` — расходы;
- `X` — допустимые исключения;
- `F` — источники финансирования;
- `Debt` — долг;
- `DS` — обслуживание долга.

### Общие доходы

```text
TotalRevenue = R + T
```

### Баланс

```text
Balance = TotalRevenue - E
```

### Дефицит

```text
Deficit = max(-Balance, 0)
```

### Отношение дефицита к доходной базе

```text
DeficitRatio = Deficit / R
```

### Базовый предел дефицита

```text
BaseLimit = R × λ
```

В текущей конфигурации `λ = 0.10`.

**Важно:** 10% — текущий технический параметр MESM. Его необходимо подтвердить/скорректировать с финансистами.

### Допустимый дефицит

```text
AllowedDeficit = BaseLimit + X
```

### Разрыв нормализации

```text
NormalizationGap = max(Deficit - AllowedDeficit, 0)
```

### Разрыв финансирования

```text
FinancingGap = max(Deficit - F, 0)
```

### Регулярный баланс

```text
RecurringBalance = RecurringRevenue - RecurringExpenditure
StructuralGap = max(-RecurringBalance, 0)
```

### Долговая нагрузка

```text
DebtAfter = max(CurrentDebt + PlannedNetBorrowing, 0)
DebtRatio = DebtAfter / R
```

Текущий технический лимит `DebtRatio = 1.00` также требует подтверждения.

### Обслуживание долга

```text
DebtServiceRatio = DS / ExpenditureBase
```

Текущий технический лимит — 0.15. Требуется подтверждение состава `ExpenditureBase` и самого лимита.

## 12. Что необходимо проверить с администрацией

- точное определение доходной базы;
- состав допустимых исключений;
- нормативный предел дефицита;
- долг: фактический долг или верхний предел;
- формулу базы для обслуживания долга;
- правила учёта субвенций;
- формулу бюджетной обеспеченности;
- перечень регулярных доходов и расходов;
- методику расчёта трансфертов и выравнивания.

После подтверждения коэффициенты переводятся из технических defaults в официально согласованный расчётный профиль.
