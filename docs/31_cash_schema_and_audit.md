# Кассовый контур: поля, формулы и аудит

## Совместимость
Новые поля необязательны при импорте старых CSV. Шаблоны, скачиваемые из экрана «Кассовый контур», содержат расширенные поля. Суммы всех файлов должны быть в одинаковых единицах. Коды читаются строками, ведущие нули сохраняются.

| Поле кассовой строки | Значение |
|---|---|
| kfsr | Раздел и подраздел расходов, 4 цифры (например, 0101) |
| kvr | Вид расходов, 3 цифры (111, 244); не код дохода |
| target_code | Целевая статья в исходном формате; длина не навязывается без справочника источника |
| document_id | ID исходного документа; не обязательно уникален по строкам многострочного документа |
| preliminary_status | operational / preliminary / final — оперативный / предварительный / окончательный |

`preliminary` сохранён для совместимости: final соответствует false, остальные статусы — true. Противоречие отклоняется. Статус не доказывает юридическое утверждение документа.

| Поле поправки | Значение |
|---|---|
| kbk | Код строки, к которой применяется поправка; NDFL_DEMO допустим только как демонстрационный код |
| kvr | Необязательная проверка вида расходов. При смешанных КВР в одном КБК расчёт останавливается: требуется разделение выгрузки. Полное распределение поправок по целевым статьям пока не реализовано |
| document_number | Номер и дата документа-основания, текст |
| effective_date | Дата начала действия; поправка недоступна до неё и до approved_at |
| is_manual | true / false, происхождение поправки. Автоматическая поправка также требует основания и утверждения |

Новые поля классификации входят в ключ выбора версии отчёта и преобразования накопленных сумм. Метаданные документа сохраняются после преобразования. Идентификатор документа не используется для автоматического удаления строк: один документ может содержать несколько проводок.

## Формулы и ограничения
Месячное исполнение = накопленная сумма текущего месяца − накопленная сумма предыдущего. Январь сравнивается с нулём. Пропущенные месяцы отклоняются.

Регулярные суммы — копия кассовых данных после утверждённых аналитических поправок. Разовые поступления исключаются; возвраты и авансы переносятся между месяцами. Это аналитическая нормализация, а не изменение официального отчёта или бюджетной росписи.

Кассовый остаток = начальный остаток + накопленные доходы + финансирование − расходы − повторно учтённые переходящие остатки. Потребность = max(−остаток, 0). При неизвестной начальной базе нулевой остаток даёт условную оценку. Дефлятор и сезонные коэффициенты поддерживаются ядром, но пока не вводятся на этом экране.

StructuralGap бюджетных лимитов и кассовые поправки относятся к разным расчётам. Нельзя считать любую поправку росписи исключением из регулярных доходов.
