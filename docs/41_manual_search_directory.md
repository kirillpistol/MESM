# Справочник поиска информации: следующий этап MESM — L3

Автор проекта вручную формулирует потребность в данных, использует запросы к другим ИИ для поиска первичных документов и проверяет результат. По описанию автора, этот способ лежал в основе разработки MESM. Это описание процесса, а не свидетельство, что каждое историческое число уже имеет сохранённое подтверждение. Доказательства определяются существующими ссылками, трассировкой и журналами сверки.

## Что работает в версии 1.14.0

Экран «Поиск информации» сохраняет ручные задачи: код, название, муниципалитет/ОКТМО, показатель, период, единицу, ожидаемый первичный источник и содержание запроса. Оператор указывает имя и явно подтверждает требования. Только после этого появляется запрос для передачи другому ИИ. Изменение любого требования аннулирует старое подтверждение; журнал сохраняет автора, время, действие и SHA-256 требований. Подтверждение требований не означает проверку найденных данных.

Публичный шаблон: `config/search_directory.json`. Локальный справочник: `data/search/directory.json`, исключён из Git; экспорт доступен в панели. Имя оператора вводится вручную: это журнал рабочего процесса, а не удостоверенная электронная подпись. Предполагается один оператор записи; многопользовательская блокировка и авторизация пока не реализованы.

## Следующий этап: поисковые микросистемы

| Этап | Проверяемое основание | Условие перехода |
| --- | --- | --- |
| Ручная постановка | Муниципалитет, показатель, период, единица, источник | Человек подтверждает конкретную версию требований |
| Поиск через другой ИИ | Запрос и ответ, ссылки, дата поиска | Ответ считается кандидатом; найденный первичный документ проверяется человеком |
| Подготовка парсера | Формат, версия парсера, схема полей, контрольный пример | Проверены код и привязка полей к документу |
| Извлечение | Хеш файла, страница/таблица/строка/ячейка, исходный текст, версия парсера | Человек сверяет значения, единицы, периоды и контрольные суммы |
| Допуск в MESM | Результаты проверки схемы, сверки рядов и дат доступности | Отдельное подтверждение пригодности для конкретного расчёта |
| Обновление | Новый документ либо изменённые требования/парсер | Повторная проверка изменившихся оснований; предыдущая история сохраняется |

Один поисковый модуль обслуживает одну понятную потребность: например, месячное исполнение 0503117 или годовую структуру НДФЛ. ИИ помогает найти кандидата; парсер воспроизводимо извлекает; человек подтверждает. Найденный файл не должен автоматически получать статус validated. Годовой ряд не доказывает месячное раннее предупреждение.

## Точки улучшения кода

`src/mesm/sources/search_directory.py` отделяет требования и журнал от реестра источников. Комментарии отмечают места расширения: адаптеры ИИ, удостоверение проверяющего и привязка подтверждений к хешам документов/извлечений. `dashboard/search_view.py` предоставляет ручной интерфейс. Автоматические запросы ИИ, загрузка документов и запуск парсеров здесь пока не выполняются.

Далее нужен реестр разрешённых парсеров с версией, схемой результата и тестовыми файлами. Код из ответа ИИ нельзя исполнять напрямую. Подтверждения источника и извлечения следует привязывать к хешам документа, требований и версии парсера; изменение любого основания требует повторной сверки. Для сервера понадобится транзакционное хранилище, роли пользователей и резервное копирование журнала. Допуск в расчёты проходит существующий контур валидации источников и импорта, а не отдельный обход проверок.

## Связь с GENESIS и обновлениями

Справочник относится к сбору и проверке данных MESM, не к вычислениям GENESIS. GENESIS получает отчётный пакет и методику через существующий API. Локальные поисковые записи не публикуются автоматически. Эта документация включена в `/v1/methodology`; её изменение меняет идентификатор методики и снимка. Новые функции выпускаются проверенными версиями с обновлением документации и тестов.
