# MESM 1.12.0: подключение ИИ и перенос на другой муниципалитет

## Что реализовано
Локальная SQLite-база data/api/mesm.sqlite: каталог таблиц, записи, муниципалитеты, метаданные снимка. API HTTP/JSON v1 только для чтения. Нет автоматического подключения к конкретной модели ИИ: клиент использует HTTP с Bearer token или читает SQLite в режиме mode=ro. Для облачного ИИ требуется отдельный защищённый хост и интеграция; localhost чужого компьютера недоступен.

Запуск Windows: сначала START_MESM.bat, затем START_MESM_API.bat. Второй скрипт создаёт временный токен, показывает его локально, строит базу и запускает API на 127.0.0.1:8765. Закрытие окна прекращает сервер. Токен не сохраняется в Git. Можно заранее задать MESM_API_TOKEN (от 24 символов). Никакой покупки базы или внешнего сервиса не требуется.

Linux: `PYTHONPATH=src python scripts/build_data_store.py`; затем с заданной переменной MESM_API_TOKEN: `PYTHONPATH=src python -m mesm.access.server`. Переменную задавайте в своём окружении, не публикуйте.

## Контракт выдачи
Все запросы требуют `Authorization: Bearer <token>`. Русские query-параметры клиент кодирует стандартным URL encoding.

| Маршрут | Назначение |
|---|---|
| GET /v1/health | Версия схемы, версия MESM, snapshot_id, built_at, число строк |
| GET /v1/catalog | Каталог, поля, частота, единица, статус основания, наличие данных |
| GET /v1/municipalities | Названия и известные ОКТМО; identity_status отмечает наличие кода, но не подтверждает актуальность границ |
| GET /v1/data?dataset=fiscal_panel&municipality=Сургут | Записи с точным фильтром по названию, period, limit (1–1000), offset |
| GET /v1/report?municipality=Сургут | Единый HTML-отчёт по пяти вопросам |
| GET /v1/sources | Снимок реестра внешних источников с историей |
| GET /v1/trace | Доступная прослеживаемость бюджета Сургута 2025; не универсальный реестр всех городов |

Пустой фильтр возвращает rows=[] и total=0; это не нулевой экономический показатель. Пропущенное значение — JSON null. 401: токен; 400: параметры; 404: неизвестный dataset/маршрут; 409: входы отчёта изменились после снимка, перезапустите API. Поля row_count/available описывают наличие, а evidence_status — основание; detector_ready всегда false: подключение к детекторам требует отдельного протокола. Для ФНС нельзя суммировать все строки: есть разные показатели, разрезы, налоговые органы и пересекающиеся итоги.

База пересоздаётся атомарно при старте API; работающая база не изменяется через API. built_at — время экспорта, не дата доступности исходного показателя. snapshot_id — SHA-256 содержания таблиц и включённых метаданных, не электронная подпись. Кассовый CSV, загруженный только в сессии Streamlit, сюда не входит. API не выдаёт реальных сигналов детекторов или измеренный эффект при отсутствии подтверждённых входов.

## Повторение для другого города
1. Создайте отдельную копию проекта/окружение. `python scripts/init_municipality.py --name "Название" --oktmo 12345678 --region "Регион" --output municipality_inputs`. Код в примере условный, замените официальным.
2. Проверьте ОКТМО, границы и историю переименований. Добавьте строку в data/reference/municipality_registry.csv по существующему контракту. Название не является официальным идентификатором.
3. Замените config/municipality_profile.json созданным профилем. Это задаёт начальный выбор интерфейса, но не создаёт данные.
4. Заполните пустые CSV реальными документами своего города. Импортируйте через «Ввод данных», начиная с reference_core, затем quality_rankings, budget_official_plan, budget_project и budget_provision. Контракты и контроль дублей уже существуют. Заполните source_url, публикации, единицы и стадию плана. Перед загрузкой очистите демонстрационные данные Сургута в отдельной копии, если они не должны быть доступны клиенту.
5. Перестройте fiscal_reference_panel штатным запуском панели. Отчёт читает активный budget_official_plan. Сургутские страницы PDF/местные нормы не переносятся на другой город. Для нового города создайте аналогичный парсер и прослеживаемость: текущий PDF-парсер специфичен для документа №713.
6. Согласуйте peer-группу своего региона. В текущем отчёте peer-контекст ХМАО демонстрационный; для иного региона его нужно заменить и проверить единицы и состав выборки.
7. Получите месячное исполнение, оперативные выгрузки, даты публикации и журнал поправок. Проверьте накопительные суммы и начальные остатки. Новые муниципальные правовые акты проверьте отдельно; универсальную правовую применимость система не устанавливает.
8. Подключите сопоставимый Predictive-ряд. Проверьте территории, период, показатель, даты доступности, сверку, отсутствие look-ahead. Только после этого допускайте его к прогнозу и детекторам.
9. Запустите pytest, сверку ручного расчёта с исходным документом и CHECK_MESM.bat. После намеренного обновления: `python scripts/snapshot_manifest.py --write`. Перезапустите API и сравните API/HTML/ручные числа для своего города.

## Проверка при приёмке
Каталог должен различать real/synthetic и отсутствующие таблицы. Запрос неизвестного города не должен выдавать Сургут. Токен требуется каждому маршруту. Проверить пагинацию, null, неточность фильтра, отказ изменений, идентичность snapshot_id при одинаковых входах, новый snapshot_id после изменения таблицы, отсутствие токенов в Git. AppTest проверяет выполнение интерфейса, но не пересечения текста в пикселях. Реальный запуск .bat и внешний ИИ проверяются на вашем ПК.
