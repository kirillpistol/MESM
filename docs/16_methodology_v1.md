# MESM Methodology v1

## 1. Что MESM пытается обнаружить

MESM не должен считать любой необычный показатель экономическим шоком.

Рабочая последовательность:

```text
Observation
→ Expected path
→ Residual
→ Standardized deviation
→ Persistence
→ Change-point confirmation
→ Cross-domain confirmation
→ Economic interpretation
→ Structural shift
```

Для показателя (X_{i,t}):

[
e_{i,t}=X_{i,t}-\hat X_{i,t}
]

[
z_{i,t}=\frac{e_{i,t}}{\sigma_i}
]

Большой residual или z-score — только кандидат на аномалию.

## 2. Четыре уровня доказательства

### Anomaly
Одиночное необычное наблюдение. Может быть вызвано сезонностью, ошибкой данных,
единичным платежом или другим разовым фактором.

### Signal
Отклонение достаточно велико, чтобы продолжать наблюдение. Это еще не WARNING.

### Early warning
Отклонение сохраняется во времени и получает независимое подтверждение.
В Predictive Layer раннее предупреждение может появиться до следующей официальной
Reference-точки.

### Structural shift
Меняется не просто значение, а режим поведения ряда: уровень, тренд, волатильность,
структура расходов или связь между экономическими факторами.

## 3. Условия подтверждения

Рабочая логика:

[
Signal = Abnormality + Persistence + Confirmation
]

Для подтвержденного структурного сдвига требуется:

[
BREAK\_CONFIRMED =
Persistence
\land
DetectorConfirmation
\land
EconomicInterpretability
]

Один CUSUM, один PELT или один плохой бюджетный показатель не должны самостоятельно
создавать BREAK_CONFIRMED.

Пороговые значения в коде являются стартовыми исследовательскими настройками.
Они должны калиброваться на development-периоде и замораживаться до финального holdout.

## 4. Экономические области

MESM группирует показатели не по файлам, а по экономическому смыслу.

| Область | Примеры показателей | Что пытаемся понять |
|---|---|---|
| Consumer Demand | реальные расходы, транзакции, средний чек, категории | меняется ли реальный спрос |
| Income & Labour | доходы, заработная плата, занятость | меняется ли покупательная способность |
| Cost of Living | CPI, топливо, транспорт, FX | усиливается ли ценовое давление |
| Business Activity | обороты SME, налоги, закупки | меняется ли деловая активность |
| Municipal Finance | доходы, revisions, долг, БО, трансферты | подтверждается ли изменение фискальным контуром |
| Economic Structure | доли категорий, коэффициенты модели | изменяется ли сама структура поведения |

В текущей публичной сборке реальные данные полноценно покрывают прежде всего
Municipal Finance. Остальные области не должны автоматически получать NORMAL:
при отсутствии данных состояние — NO_DATA.

## 5. Reference Layer

Reference Layer — официальный или нормативный контур.

Текущие доступные признаки:

- отклонение фактических доходов от первоначального плана;
- доля программных расходов;
- число изменений бюджета;
- долговая нагрузка;
- официальный ранг качества управления;
- бюджетная обеспеченность, где она доступна.

Текущие peer-пороги используются только для скрининга. Например, 75-й перцентиль
не является откалиброванным порогом экономического стресса.

## 6. Predictive Layer

Целевая логика Predictive Layer:

```text
Consumer activity
+ Income
+ Employment
+ Fuel
+ CPI
+ FX
+ Oil / external factors
→ expected path
→ residual
→ detectors
→ early signal
```

До подключения реальных высокочастотных данных Predictive Layer не должен
создавать реальный EARLY_WARNING по муниципалитету.

## 7. Lead Time

Ключевая гипотеза MESM — возможность увидеть изменение раньше официального
фискального подтверждения.

[
LeadTime =
t_{ReferenceConfirmation}
-
t_{PredictiveSignal}
]

Положительное значение означает, что Predictive Layer подал сигнал раньше.

## 8. Состояния

Для одного временного контура:

```text
NORMAL → OBSERVE → WARNING → BREAK_CONFIRMED
```

- NORMAL — значимого устойчивого отклонения нет.
- OBSERVE — появился кандидат на сигнал.
- WARNING — сигнал устойчив и требует наблюдения.
- BREAK_CONFIRMED — persistence и независимые детекторы подтверждают изменение режима.

До temporal backtest текущий годовой Reference-скрининг не должен напрямую
присваивать эти состояния.

## 9. Экономический вывод

Пользовательский вывод должен отвечать на вопросы:

1. Что изменилось?
2. Когда началось изменение?
3. Насколько оно необычно?
4. Как долго сохраняется?
5. В каких экономических областях оно видно?
6. Какие факторы статистически согласуются с изменением?
7. Подтверждает ли сигнал официальный Reference Layer?
8. Каково качество данных и сила доказательства?

Формулировки о причинах должны быть осторожными. Если модель не имеет причинной
идентификации, MESM пишет «согласуется с», «совпадает по времени», «имеет вклад в
прогноз», а не «вызвано».

## 10. Текущий статус

На текущем этапе MESM умеет формировать реальный публичный Fiscal Reference Panel,
скрининговые флаги и фискальную интерпретацию. Shock Monitor с CUSUM/PELT пока
является демонстрацией механики на синтетическом residual-ряде.

Следующий исследовательский шаг — реальный temporal Predictive Layer и backtest
Signal → Warning → Structural Shift.
