# MESM — карточка модели

## Назначение

Раннее обнаружение и объяснение устойчивых изменений в муниципальной экономике и бюджетном состоянии для поддержки аналитических решений.

## Что уже реализовано

Публичное ядро содержит Fiscal / Reference слой, машину состояний двух контуров, temporal backtest, основные метрики качества, защиту от некорректной работы с YTD и simulation framework для проверки детектора на контролируемых шоках.

Потребительская модель на реальных банковских данных пока не обучена.

## Логика состояний

Контур проходит через `NORMAL`, `OBSERVE`, `WARNING`, `BREAK_CONFIRMED`. Для защиты от дрожания около порога используется hysteresis. Подтвержденный структурный сдвиг требует не только длительного превышения порога, но и дополнительного подтверждения.

Итоговый Dual State: `NORMAL`, `EARLY_WARNING`, `FISCAL_DIVERGENCE`, `SYSTEMIC_STRESS`.

## Ground truth

Бюджетное уточнение может использоваться как последующее подтверждение при расчете LeadTime, но не должно автоматически становиться независимым label для проверки того же бюджетного контура. Для каждого события сохраняются источник, уверенность и риск circular evaluation.

## Синтетические данные

Синтетический consumer layer и искусственно внесенные шоки используются только для тестов пайплайна, power analysis, stress tests и демонстраций. Результаты на синтетике не считаются доказательством качества на реальных данных.

## Для кого проект

Аналитики, data scientists, команды стратегии и риска, исследователи муниципальных финансов.

## Для чего проект не предназначен

MESM не используется для индивидуальных кредитных решений, автоматического изменения бюджетной политики, подмены официальной методологии или работы с защищенной персональной информацией.

## Валидация

Заявлять качество модели можно только после проверки на финальном временном holdout с заранее зафиксированными порогами и `as_of`-логикой.

## Жизненный цикл

Используется Champion / Challenger подход. Переобучение может запускаться автоматически, но перевод новой модели в production требует проверки; предыдущая рабочая версия должна оставаться доступной для rollback.
